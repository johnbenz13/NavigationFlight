## Acceptance criteria

- [ ] Arm is enabled only for a valid forward route and complete usable values for every formed replacement leg, with current departure eligibility. Explain missing reasons.
- [ ] No separate Validate or Start now exists in preparation/armed inspection. Opening/closing, saving or becoming Ready never changes the operational route.
- [ ] Arm uses existing scheduled effect, including shortened current destination where appropriate, and preserves current elapsed timer.
- [ ] Show pending/saving guard during commit; return to Cockpit and show Armed only after durable success.
- [ ] Failure/uncertain outcome preserves latest draft and last committed route; Retry cannot duplicate confirmation/events.
- [ ] After success, cleanup/recovery cannot resurrect the accepted draft as unarmed; preserve existing armed durable recovery.
